# me/day — Me Per Day

사진 한 장이면 기록 완료. 기존 v0.1 ZIP의 HTML/CSS/JavaScript 화면과 수동 기록 기능을 재사용한 MVP입니다.

## 연결 대상

- GitHub: https://github.com/mzsdz/meperday
- Vercel: 기존 `mzsdz/meperday`, project `prj_N34shwrwrBmVLJ5hbuw8Wm86jVTb`
- Supabase: 기존 `xbclkxeexrhdqhxafuad` (meperday)

새 클라우드 프로젝트를 만들지 않습니다.

## 개발

Node.js 22.12 이상(배포는 24), `npm ci` 후 `.env.example`을 `.env.local`로 복사하고 공개 Supabase URL/키를 설정합니다.

```
npm run dev
npm test
npm run test:e2e
npm run build
```

로컬 E2E는 설치된 Edge, CI는 Ubuntu 24.04 실행 이미지에 설치된 Google Chrome을 사용합니다. CI에서 브라우저 및 운영체제 패키지를 다시 설치하지 않으며, Chrome 버전을 확인한 뒤 동일한 모바일 E2E를 실행합니다. 작업 제한 시간은 10분입니다. 환경변수 없이 실행하면 화면에 **로컬 모드**를 표시하고 브라우저에 저장합니다. Supabase가 설정된 운영 앱도 로그인 없이 첫 화면에서 사진을 기록할 수 있으며, 이때는 **이 기기에 저장 · 계정 동기화 꺼짐**을 표시합니다. 로그인은 선택 버튼으로 열고 언제든 닫을 수 있습니다. 로그인한 계정의 서버 조회나 저장이 실패하면 로컬 저장 성공으로 바꾸지 않습니다. 기기 기록은 로그인 후 설정에서 **이 기기 기록을 계정에 가져오기**를 눌러 가져올 수 있으며, 기존 계정 기록을 덮어쓰지 않습니다. 브라우저 데이터를 지우기 전 JSON 백업을 권장합니다.

## 저장과 로그인

Supabase 이메일 로그인 링크로 같은 계정에 다시 접속합니다. Supabase Auth의 Site URL과 Redirect URLs에 배포 주소 및 개발 주소를 허용해야 합니다. 이메일 전달은 Supabase 이메일 공급자/SMTP 설정과 발송 제한을 따릅니다.

`meday_journals`에는 사용자별 식사·운동·평가·하루 기준량 JSON과 revision을 저장합니다. MVP에서 기존 데이터 구조를 보존하기 위한 단일 행 설계입니다. 사용자 기본키와 RLS로 다른 계정의 읽기·쓰기·삭제를 차단합니다. 조건부 revision 갱신은 다른 기기의 변경을 덮어쓰지 않게 하며 충돌하면 새로고침 후 다시 저장해야 합니다. 대량 데이터 검색/분석을 확장할 때 식사·운동 테이블 분리를 권장합니다.

사진은 비공개 `meday-photos` 버킷의 `user-id/sha256.jpg`에 저장하고 DB에는 경로만 저장합니다. 다운로드에는 1시간 유효 서명 URL을 사용하며 화면이 닫혀 있을 때 주기적으로 갱신합니다. 새 사진 등록은 불변 경로를 사용하므로 기존 사진을 덮어쓰지 않습니다. 기록 삭제 후 참조가 없어진 사진은 동시 업로드를 보호하기 위해 자동 삭제하지 않습니다. 별도의 보관/정리 정책은 후속 작업입니다. 백업은 서명 URL 대신 이미지 데이터를 포함합니다.

`supabase/migrations`의 SQL은 기존 프로젝트에 적용되어 있습니다. 재적용하지 말고 마이그레이션 이력을 확인하세요. 공개 테이블에 RLS를 자동 설정하는 기존 이벤트 트리거의 일반 사용자 실행 권한도 제한했습니다.

## 구현 범위

- 모바일 일간/주간/월간, 아침·점심·저녁, 끼니 상세, 기록 수정·삭제
- 음식 사진만 저장 가능, 음식명/열량/영양소/섭취량 수정 및 가격·식당·메모 선택 입력
- 원본 EXIF DateTimeOriginal을 압축 전에 읽음. 없으면 빈칸, 업로드 시각으로 대체하지 않음. 시간 수정은 기존 기록 상세 편집에서만 가능
- 운동 캡처만 저장 가능, 미확인 운동 시간·열량은 빈칸
- 9개 영양소의 하루 기준, 나트륨·포화지방은 별도 상한으로 표시
- 미확인 열량을 0으로 계산하지 않음. 주간/월간 평균은 알려진 열량이 있는 날짜 기준이며 부분 합계를 표시
- 끼니/하루 평가 선택 입력. 알림·완성도 점수 없음
- 현재 섭취 영양소·과거 음식·반복 선택·식사 평가를 이용한 규칙 기반 메뉴 3개 추천. 자동 섭취 기록 없음
- 계정 서버 저장, 비공개 사진, 실패/충돌 처리, JSON 백업/복원
- 링크 공유용 Open Graph/Twitter 메타데이터와 1200×630 PNG

## Google 로그인

로그인 화면은 Google 제공자 설정을 Supabase 공개 설정 API로 확인한 뒤 Google로 계속하기를 활성화합니다. Google Cloud 웹 OAuth 클라이언트의 원본은 `https://meperday.vercel.app`, 콜백은 `https://xbclkxeexrhdqhxafuad.supabase.co/auth/v1/callback`입니다. Client ID와 Secret은 기존 Supabase 프로젝트의 Google 제공자 설정에 직접 저장합니다. 앱 코드나 Vercel에는 Google Secret을 넣지 않습니다. 로그인 취소/연결 오류 시 이메일 로그인과 기기 기록을 유지합니다. 인앱 브라우저에서 Google이 로그인을 제한할 경우 Safari 또는 Chrome에서 열어야 할 수 있습니다.

## AI 분석

`api/analyze.js`는 Vercel AI Gateway와 AI SDK의 구조화된 응답을 사용합니다. 모델은 서버 전용 `AI_GATEWAY_MODEL`이며 기본값은 현재 모델 목록에서 vision/structured-output을 확인한 `google/gemini-3.8-flash`입니다. 기존 Vercel 배포 OIDC가 제공되면 사용하고, 별도 서버 키가 필요하면 Vercel 환경변수에 `AI_GATEWAY_API_KEY`를 직접 설정합니다. OIDC 설정을 새로 활성화하거나 결제 수단/크레딧·자동 충전을 임의로 변경하지 않습니다.

사용자는 로그인 후 사진 분석 버튼을 눌러 요청합니다. 사진 선택만으로 AI 제공자에게 전송하지 않습니다. 서버는 Supabase에서 토큰을 검증하고, 기존 DB의 비공개 사용량 테이블로 계정별 하루 20회 요청을 원자적으로 제한합니다(한국 날짜 기준). 실패한 제공자 요청도 한도에 포함됩니다. 게스트/키 없음/인증 만료/크레딧 부족/한도 초과는 명시적인 오류이며 가짜 분석 결과를 만들지 않습니다. 수동 기록은 계속 사용할 수 있습니다.

음식 분석은 추정치로 표시하고 개별 영양소가 불확실하면 null로 남깁니다. 매장·구매처·가격·시간을 AI가 채우지 않습니다. 운동 캡처도 실제 읽히지 않는 값은 null입니다. 사용자는 결과를 수정한 뒤 저장할 수 있습니다. 이전 공용 MVP_ACCESS_CODE 설정은 사용하지 않습니다. 기본 영양 기준과 규칙 기반 메뉴 추천은 기존 동작을 유지합니다.

## 검증

모바일 업로드 폼은 320·393·430px에서 음식·운동 사진 선택창 열기, 업로드 영역의 단일 테두리와 전체 너비, 가로 넘침, 사진만 저장 후 재조회를 검증합니다. 기본 CI의 Chrome 검사와 별도로 Windows WebKit 작업도 같은 검사를 실행합니다. WebKit은 Safari와 같은 엔진이지만 실제 iPhone Safari의 OS 사진 선택창까지 동일한 환경은 아닙니다. 로컬에서는 `npx playwright install webkit` 후 `PLAYWRIGHT_WEBKIT=1` 환경변수를 설정하고 `npm run test:e2e -- --project=webkit-upload`로 실행할 수 있습니다.

- `npm test`: EXIF/미확인 열량, 백업 입력 검증, 서버 사진 저장 경로·재조회, 동시 수정 거부, AI 미설정 처리
- `npm run test:e2e`: Supabase 설정 유무를 분리해 모바일·데스크톱 첫 방문/로그인 창 닫기/전송 실패 후 복구/게스트 사진 저장을 검증하고, 모바일 로컬 사진 단독 저장→재접속→주간/월간, 메뉴 추천 비자동기록, 운동 캡처 단독 저장
- `scripts/verify-live.mjs`: 명시적으로 제공한 테스트 관리자 키로 임시 QA 사용자 2개를 만들고 실제 Supabase 사진 업로드·서명 다운로드·DB 재조회·수정·다른 계정 접근 차단을 확인한 뒤 사용자와 사진을 정리합니다. `VERIFY_BROWSER_URL` 설정 시 세션 주입 없이 첫 방문→게스트 사진 저장→진짜 Supabase 로그인 링크 콜백→명시적 기기 기록 가져오기→계정 사진 저장→새로고침을 확인합니다. 링크는 테스트 관리자 API로 생성하므로 메일을 발송하지 않으며 실제 메일 전달은 별도 검증이 필요합니다. 비밀 키는 저장소/브라우저에 넣지 않습니다.

개인 정보는 OG 이미지에 포함하지 않습니다. Vercel Preview의 기존 배포 보호를 유지하므로 외부 공유 크롤러가 보호된 Preview의 이미지에 접근하지 못할 수 있습니다. 공개 도메인 연결 후 미리보기 접근을 다시 확인해야 합니다.


## 모바일 전체 흐름 점검

사진 처리 중에는 저장을 잠그고, 닫은 폼의 이미지 처리 결과가 다른 폼에 반영되지 않게 합니다. 파일 MIME 정보가 없거나 부정확하면 JPEG/PNG/WebP 등의 실제 서명을 확인합니다. 원본 촬영 시간은 사진 처리 성공 후에만 갱신하며 실패한 사진 교체는 기존 사진과 시간을 보존합니다. HEIC는 해당 브라우저가 디코딩할 수 있을 때 처리하며, 지원하지 않는 파일은 JPEG/PNG로 내보내라는 안내를 표시합니다.

키보드로 화면 높이가 줄어들 때 visualViewport에 맞춰 시트 높이를 조정합니다. 회전 EXIF 사진, 사진 교체, 끼니/날짜/시간/선택 입력 수정, 삭제 취소/확정, 기기 저장 공간 부족 후 재시도, 만료 로그인 링크와 기기 기록 보존을 Chrome 및 모바일 WebKit에서 검사합니다. 새 탭의 로그인은 원래 탭에도 반영하고, 다른 탭에서 로그아웃하면 이전 계정 화면을 유지하지 않습니다. 계정 기록을 조회하는 중에는 편집을 열지 않습니다.

실제 Supabase 검증은 `VERIFY_BROWSER_ENGINE=webkit`로도 실행할 수 있습니다. 새 탭에서 진짜 로그인 링크 열기→기기 기록 가져오기→계정 사진 교체/수정→서버 저장 실패 주입/재시도→식사·운동 삭제→로그아웃/재로그인→재조회를 확인합니다. 임시 QA 계정과 사진은 정리하며 실제 사용자에게 테스트 메일을 발송하지 않습니다. 실제 iPhone 사진 선택 UI, 가상 키보드의 OS 동작, 메일 수신함까지의 전달은 자동화된 WebKit 검증과 별개입니다.

## 기록 보상 포인트와 몸무게 인증

- AI 음식·운동 분석은 포인트를 차감하지 않습니다. 기존 하루 20회 AI 호출 보호 한도는 유지됩니다.
- 로그인 후 계정에 처음 저장하는 아침·점심·저녁·운동·몸무게에 각각 200P. 한국 시간 기준 항목별 하루 한 번, 최대 1,000P입니다. 간식은 적립 대상이 아닙니다.
- 같은 기록 날짜와 항목은 삭제 후 새 ID로 다시 등록해도 다시 적립되지 않습니다. 기록 ID도 별도로 보존하므로 날짜/항목을 수정하거나 원래 ID를 다시 가져와도 재지급되지 않습니다.
- 과거 기록을 새로 입력해도 실제 저장한 날의 항목별 한도에 포함됩니다. 미래 날짜는 적립하지 않습니다. 적용 전 계정 기록은 소급 지급하지 않습니다.
- 포인트는 저널 저장 트랜잭션의 서버 트리거에서만 생성합니다. 원장은 본인 읽기만 허용하며 사용자가 잔액/원장을 직접 변경할 수 없습니다. 기록 삭제 후에도 받은 포인트와 중복 방지 이력은 유지됩니다.
- 포인트 잔액/오늘 적립/최근 20건을 상단 ‘내 포인트’에서 확인할 수 있습니다. 포인트 조회 장애는 기록 저장을 취소하지 않습니다. 충전·차감·현금 교환 기능은 구현하지 않습니다.
- 몸무게 인증은 비공개 체중계 사진으로 저장합니다. kg·메모는 선택이며 사진에서 체중을 추측하거나 실제 체중을 검증하지 않습니다. 수정·삭제·백업·기기 기록 가져오기를 지원합니다.
- 기존 백업은 그대로 가져올 수 있고, 새 백업에는 몸무게 인증 사진과 선택 수치도 포함됩니다. 포인트는 백업 파일에 의존하지 않습니다.

검증: `npm test`, `PLAYWRIGHT_WEBKIT=1 npm run test:e2e -- --workers=2`, `tests/points-db.sql`(실행 후 항상 롤백), 실제 프로젝트 임시 계정 검증 `scripts/verify-points.mjs`. 운영 모델은 `AI_GATEWAY_MODEL=openai/gpt-4o-mini`로 설정되어 있습니다.
