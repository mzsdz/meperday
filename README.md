# me/day — Me Per Day

사진 한 장이면 기록 완료. 기존 v0.1 ZIP의 HTML/CSS/JavaScript 화면과 수동 기록 기능을 재사용한 MVP입니다.

## 연결 대상

- GitHub: https://github.com/mzsdz/meperday
- Vercel: 기존 `mzsdz/meperday`, project `prj_N34shwrwrBmVLJ5hbuw8Wm86jVTb`
- Supabase: 기존 `xbclkxeexrhdqhxafuad` (meperday)

새 클라우드 프로젝트를 만들지 않습니다.

## 개발

Node.js 22.12 이상(배포는 24), `npm ci` 후 `.env.example`을 `.env.local`로 복사하고 공개 Supabase URL/키를 설정합니다.

```
npm run dev
npm test
npm run test:e2e
npm run build
```

로컬 E2E는 설치된 Edge, CI는 Ubuntu 24.04 실행 이미지에 설치된 Google Chrome을 사용합니다. CI에서 브라우저 및 운영체제 패키지를 다시 설치하지 않으며, Chrome 버전을 확인한 뒤 동일한 모바일 E2E를 실행합니다. 작업 제한 시간은 10분입니다. 환경변수 없이 실행하면 화면에 **로컬 모드**를 표시하고 브라우저에 저장합니다. Supabase가 설정된 배포에서는 로그인과 서버 조회가 성공해야 기록할 수 있으며, 연결 실패를 로컬 저장 성공으로 바꾸지 않습니다. 로컬 기록은 계정에 자동 병합하지 않습니다. 필요하면 설정의 JSON 내보내기/불러오기를 사용합니다.

## 저장과 로그인

Supabase 이메일 로그인 링크로 같은 계정에 다시 접속합니다. Supabase Auth의 Site URL과 Redirect URLs에 배포 주소 및 개발 주소를 허용해야 합니다. 이메일 전달은 Supabase 이메일 공급자/SMTP 설정과 발송 제한을 따릅니다.

`meday_journals`에는 사용자별 식사·운동·평가·하루 기준량 JSON과 revision을 저장합니다. MVP에서 기존 데이터 구조를 보존하기 위한 단일 행 설계입니다. 사용자 기본키와 RLS로 다른 계정의 읽기·쓰기·삭제를 차단합니다. 조건부 revision 갱신은 다른 기기의 변경을 덮어쓰지 않게 하며 충돌하면 새로고침 후 다시 저장해야 합니다. 대량 데이터 검색/분석을 확장할 때 식사·운동 테이블 분리를 권장합니다.

사진은 비공개 `meday-photos` 버킷의 `user-id/sha256.jpg`에 저장하고 DB에는 경로만 저장합니다. 다운로드에는 1시간 유효 서명 URL을 사용하며 화면이 닫혀 있을 때 주기적으로 갱신합니다. 새 사진 등록은 불변 경로를 사용하므로 기존 사진을 덮어쓰지 않습니다. 기록 삭제 후 참조가 없어진 사진은 동시 업로드를 보호하기 위해 자동 삭제하지 않습니다. 별도의 보관/정리 정책은 후속 작업입니다. 백업은 서명 URL 대신 이미지 데이터를 포함합니다.

`supabase/migrations`의 SQL은 기존 프로젝트에 적용되어 있습니다. 재적용하지 말고 마이그레이션 이력을 확인하세요. 공개 테이블에 RLS를 자동 설정하는 기존 이벤트 트리거의 일반 사용자 실행 권한도 제한했습니다.

## 구현 범위

- 모바일 일간/주간/월간, 아침·점심·저녁, 끼니 상세, 기록 수정·삭제
- 음식 사진만 저장 가능, 음식명/열량/영양소/섭취량 수정 및 가격·식당·메모 선택 입력
- 원본 EXIF DateTimeOriginal을 압축 전에 읽음. 없으면 빈칸, 업로드 시각으로 대체하지 않음. 시간 수정은 기존 기록 상세 편집에서만 가능
- 운동 캡처만 저장 가능, 미확인 운동 시간·열량은 빈칸
- 9개 영양소의 하루 기준, 나트륨·포화지방은 별도 상한으로 표시
- 미확인 열량을 0으로 계산하지 않음. 주간/월간 평균은 알려진 열량이 있는 날짜 기준이며 부분 합계를 표시
- 끼니/하루 평가 선택 입력. 알림·완성도 점수 없음
- 현재 섭취 영양소·과거 음식·반복 선택·식사 평가를 이용한 규칙 기반 메뉴 3개 추천. 자동 섭취 기록 없음
- 계정 서버 저장, 비공개 사진, 실패/충돌 처리, JSON 백업/복원
- 링크 공유용 Open Graph/Twitter 메타데이터와 1200×630 PNG

## AI: 선택 연결

기존 `api/analyze.js` Vercel API를 보존했습니다. 서버 전용 `OPENAI_API_KEY`, `MVP_ACCESS_CODE`가 모두 있어야 실행됩니다. 모델은 `OPENAI_MODEL`로 변경할 수 있습니다. 앱 설정에 같은 접근 코드를 입력하고 사진 분석 버튼을 누르면 사진을 분석 서버로 전송합니다. 키가 없으면 503 안내만 반환하고 가짜 분석 결과를 만들지 않습니다. 수동 저장은 계속 작동합니다.

실제 AI 영양 추정·운동 OCR은 키가 없어 검증하지 않았습니다. 코드 공유 방식은 소규모 MVP용이며 사용자별 AI 할당량·비용 제한·정교한 개인화 추천은 후속 작업입니다. 현재 추천은 규칙 기반으로 명시합니다. 섭취량 메모는 영양 수치를 자동 비례 계산하지 않으며 입력 수치는 실제 먹은 양 기준입니다. 화면의 기본 영양 기준은 목업의 임시값을 유지한 것으로 설정에서 변경할 수 있습니다.

## 검증

- `npm test`: EXIF/미확인 열량, 백업 입력 검증, 서버 사진 저장 경로·재조회, 동시 수정 거부, AI 미설정 처리
- `npm run test:e2e`: 모바일 로컬 사진 단독 저장→재접속→주간/월간, 메뉴 추천 비자동기록, 운동 캡처 단독 저장
- `scripts/verify-live.mjs`: 명시적으로 제공한 테스트 관리자 키로 임시 QA 사용자 2개를 만들고 실제 Supabase 사진 업로드·서명 다운로드·DB 재조회·수정·다른 계정 접근 차단을 확인한 뒤 사용자와 사진을 정리합니다. `VERIFY_BROWSER_URL` 설정 시 실제 브라우저 업로드→DB 저장→새로고침도 확인합니다. 비밀 키는 저장소/브라우저에 넣지 않습니다.

개인 정보는 OG 이미지에 포함하지 않습니다. Vercel Preview의 기존 배포 보호를 유지하므로 외부 공유 크롤러가 보호된 Preview의 이미지에 접근하지 못할 수 있습니다. 공개 도메인 연결 후 미리보기 접근을 다시 확인해야 합니다.
